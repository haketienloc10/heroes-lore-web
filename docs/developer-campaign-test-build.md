# Developer campaign test build

The test profiles start through the ordinary New Game menu and are available only in Vite development mode; production builds ignore the query parameter. `max-level` and `loot-survival` use the maximum accepted value for all four attributes. `damage-survival` keeps level-1 Ronin combat stats for an ordinary incoming-damage formula while raising only HP to the maximum supported value.

Start Vite on a separate local port so the browser uses an isolated origin and does not reuse the normal development site's saved data:

```sh
npm run dev --workspace web -- --host 127.0.0.1 --port 5174 --strictPort
```

Open `http://127.0.0.1:5174/?testProfile=max-level`, then start New Game through the title menu. The gameplay host gets `data-test-profile="max-level"` while the profile is active. The profile starts at level 99, with 32,767 in each attribute and full HP/SP after the starting equipment is applied. If an encounter still reduces HP to zero, the DEV test profile restores HP/SP instead of entering Game Over. M912 extracts this guard into a pure helper and adds regression tests for both developer profiles and the ordinary no-profile path. Use this for campaign routes where rewards do not depend on player level.

For an isolated map render and movement check, open `http://127.0.0.1:5174/?testProfile=max-level&testScenario=map-preview-13` and start New Game through the title menu. Replace `13` with a byte-sized map ID whose generated map, collision, decoration, and event assets are available. The DEV preview keeps fresh New Game flags, places Ronin on the nearest unoccupied ordinary floor cell near the map center, and retains the level-99 survival profile. This direct map seed can check that map's rendering and live controls; it does not verify natural campaign reachability, branch-specific flags, or J2ME parity. To capture an isolated Chromium run, use `HEROES_LORE_ROUTE_TARGET=map-preview HEROES_LORE_MAP_ID=13 node tools/campaign_browser_probe.mjs` while the local Vite server is running. The result marks `mapStateSeeded: true`.

While a developer test profile is active, the gameplay host exposes read-only route telemetry through `data-test-map-id`, `data-test-player-tile-x`, `data-test-player-tile-y`, `data-test-hp`, and `data-test-level`. `data-test-runtime` contains a v7 JSON snapshot with map dimensions and the exact current entity-occupied map cells, player resources/facing, wallet, inventory stacks and equipment instance bytes, the five equipped slots, current-map ground drops, game and quest flags, active skill action/cooldown and defense-boost timer, combo stage/style/frame/queue/recovery/timing and combo limit, dialog/transition state, current-map enemy IDs, pixel/tile positions, HP/lifecycle, behavior type/timing, animation direction/state/frame, attack cooldown/hit resolution, pursuit target/progress, on-screen state, and NPC IDs, positions at pixel and tile precision, facing, visibility, movement, and cell occupancy. The occupied-cell list comes from the same live entity-occupancy set that blocks player movement; it updates from the current world scene during the game loop. These attributes do not control gameplay or read/write saves; they are absent from production runs.

For level-sensitive item drops such as Mithril, use `http://127.0.0.1:5174/?testProfile=loot-survival`. This profile keeps the same boosted attributes and HP/SP restoration but starts at level 1, because the source Mithril chance is `20 + enemy reward code - player level`; at level 99 that chance is below zero for the available enemies. It still starts through visible New Game and does not change the map, enemies, campaign flags, events, or inputs.

For live incoming-damage probes, use `http://127.0.0.1:5174/?testProfile=damage-survival`. It starts at level 1 with Ronin's base Power/Agility/Will and a 393,216 HP pool, so low-level enemy damage can be observed while the route stays safe. The current DEV build compensates the recovery calculation back to the class's base HP attribute plus equipment HP bonuses, keeping the large pool from accelerating recovery. Use `max-level` for high-level route and screen checks; its maximum Power and Agility can reduce or avoid ordinary enemy damage and therefore cannot establish those damage outcomes.

The profiles are held in memory and do not change production code paths or write a save automatically. Use the separate port for any manual Save Game action; its browser storage belongs to that local origin only. They are intended for route and item-flow inspection. The boosted attributes and survival guard change combat outcomes, so they do not verify ordinary-level balance, death behavior, or J2ME combat parity.

For routes that need a held directional input across multiple game updates, run `node tools/campaign_browser_probe.mjs`. It launches an owned **headless Chromium** process with a temporary profile, starts New Game through normal game UI keyboard events, and holds a key until route telemetry reports a map transition. It captures screenshots of the rendered page and reads only the DEV runtime attributes. The probe does not inspect browser storage, trigger Save/Load, or seed gameplay state; the app uses the fresh profile for ordinary startup.
