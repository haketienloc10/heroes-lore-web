# FND-0025 — NPC sprite animation tracks and scripted facing

## Scope

Decode the pinned game's `/npc/spr/N` image-component tracks and render the opening NPC's source-commanded facing changes. This finding covers sprite selection and frame composition; it does not establish complete NPC behavior or animation timing parity.

## Source evidence

- JAR: `original/heroes-lore-v2.1.2.jar`, SHA-256 `7eb032297967f5d8382cc4f1ab5c3016459e01b235b42a3b88c6a8bfe46c5f61`.
- `reverse-engineering/decompiled/sources/defpackage/cd.java:b(byte,byte)` reads `/npc/spr/N` records and stores their byte payloads in `cd.j`. JADX's local-variable rendering presents the state and direction bytes as booleans; `javap -c -p cd` shows raw byte loads and the `state * 4 + direction` track index. The recorded direction indices are 0–3.
- `reverse-engineering/decompiled/sources/defpackage/ab.java:a(Graphics,int,int)` selects the standing track when `h != 2`, or the moving track when `h == 2`, then indexes it by `j - 1`. It draws each component frame and increments `k`, wrapping at the state-specific frame count. This establishes the two rendered states, four facings, and source frame-advance behavior in the renderer.
- Source paint cadence is paced by `br`: its frame-rate table is `{8, 10, 14, 18}`, the constructor selects index 2 (14), and `br.a(int)` sets the wait period to `1000 / rate`. The Options handler in `bd` exposes indices 0–2, so the selectable rates are 8, 10, and 14. In the pinned runtime trace, gameplay scheduler, `ar.paint`, and `m.i` each ran at 14 Hz with median intervals near 71.3 ms (FND-0004). The trace confirms their default-setting cadence; it does not measure the other two option values.
- `ab.a(Graphics,...)` checks the NPC's screen-space origin against margins before drawing or advancing `n.k`: `x + 16 >= 0`, `y >= 0`, `x - 16 <= screenWidth`, and `y <= screenHeight + 32` (verified from the pinned `javap -c -p ab` method). An NPC outside these bounds keeps its prior animation frame until it becomes visible again.
- `ab.mo107a()` is final and always returns false. `n.e()` calls this hook only for an actor already in moving state 2/4, then calls its eight-pixel movement step unconditionally; the hook does not choose a destination or movement direction. The map update loop calls `ab.d()`, while event commands 15–17 set scripted NPC motion/facing (FND-0026). Ordinary NPC pathfinding and autonomous wandering are therefore not source behaviors.
- The converter found eight resources: `/npc/spr/{05,08,11,12,13,14,16,17}`. Each contains all eight state/direction tracks. NPC16 has one standing frame for each direction and four moving frames for each direction. Component records preserve signed pixel offsets, mirror flags, and image indices.
- The map loader has two additional actor-image codes that do not use `/npc/spr`: `ad.m6b` maps code 3 to `/enm/17` and code 6 to `/enm/20`, loading their animation records through `cd.a(..., true)`. The NPC renderer selects only the source idle and walking tracks from those enemy records. Extracted placements use code 6 on maps 03 and 51 and code 3 on maps 62 and 71; see [FND-0044](FND-0044-special-map-npc-sprites.md).
- The extracted map-00 script 9 includes command `[17,1,4]`, which turns source NPC placement slot 1 to direction 4 (right in the web direction mapping). Map startup operation 2 leaves NPC16 at that source placement while hiding slots 2, 0, and 4; see [FND-0023](FND-0023-map-startup-operations.md) and [FND-0024](FND-0024-opening-cutscene-interpreter.md).

## Browser implementation

- `tools/extract_game_assets.py` emits `npc-animations/catalog.json` from the pinned resource bytes and validates the complete two-state/four-direction track set, frame payloads, and consistent frame counts by state. M162 adapts the idle/walk tracks from `/enm/spr/17` and `/enm/spr/20` for actor-image codes 3 and 6 and loads their existing `/enm/17` and `/enm/20` image atlases.
- `web/src/world/npc-sprites.ts` validates the generated catalog, selects tracks/frames by NPC ID/state/facing, and checks the source visibility margins. `web/src/rendering/WorldScene.ts` loads component images used by visible placements, composes offset/mirrored frames in Phaser containers, applies the opening interpreter's per-placement direction and movement state, and advances NPC frames only while they fall within the camera's source bounds.
- M159 ports the visibility gate before the source frame counter advances. M161 keeps initially hidden actors available for later visibility restoration and rebuilds collision occupancy from each visible actor's live source pixel position and standing/moving state. M165 initially advanced browser NPC frames by elapsed 71 ms world updates, based on the recorded gameplay update period in FND-0004. M312 traced the post-draw `k` increment but incorrectly tied browser advances to every Phaser post-render pass. M315 preserves the source draw-then-advance order while counting paced source gameplay passes from the scaled world-update boundaries; the cursor advances by that count after Phaser `POST_RENDER`, so additional browser RAF draws do not accelerate NPC animation. At the default 14 FPS, FND-0004 measured scheduler, paint, and `m.i` at matching 14 Hz cadence. The web's selected 8/10/14 settings follow the checked-in source rate table, but runtime cadence at 8 and 10 FPS has not been measured. The initial `k = -1` cursor resolves to frame 0 for the first paint and advances after that pass. The controlled [map-71 capture](../../reference/screenshots/web-render/M165-map71-npc-cadence/capture.json) documents the earlier browser implementation and does not establish source paint timing. M58 adds source emotion overlays to NPC sprite containers for ordered cutscene commands 50; ordinary NPC pathfinding and autonomous wandering are absent from the source actor update; general interaction behavior and emotion behavior outside supported cutscenes remain incomplete.
- M294 moves NPC atlas selection into `sourceNpcTextureSource()` in `web/src/world/npc-sprites.ts`, which is also used by `WorldScene`'s texture queue. `npm run audit:npc-render-coverage --workspace web` checks the generated initial placements plus opcode-41 script and opcode-110 startup image changes for all 72 class-6 event bundles against those same paths and every referenced frame file. It covers 88 placements, 4 script image changes, 4 startup image changes, and 34 image IDs (10 animated and 24 static) with no missing texture paths. This confirms generated asset coverage, not rendered-frame fidelity or runtime visibility.
