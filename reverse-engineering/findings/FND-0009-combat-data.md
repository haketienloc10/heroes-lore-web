# FND-0009 — Enemy data records and damage arithmetic

## Scope

Decode the enemy definition tables and identify the damage calculation sequence that can be ported without inventing encounter behavior.

## Baseline and tools

- JAR: `original/heroes-lore-v2.1.2.jar`, SHA-256 `7eb032297967f5d8382cc4f1ab5c3016459e01b235b42a3b88c6a8bfe46c5f61`.
- Read-only resource inspection: `unzip -p original/heroes-lore-v2.1.2.jar enm/data0` and equivalent for `data1` / `data2`; local Python parser checked record boundaries.
- Static source: JADX output at `/tmp/heroes-lore-jadx/sources/defpackage/{i,ak,au,t}.java`.
- Bytecode cross-check: `javap -classpath original/heroes-lore-v2.1.2.jar -p -c i au t ad`.
- Implementation: `tools/extract_game_assets.py`, `web/src/world/combat.ts`.
- Verification: `python3 -m unittest tools/test_extract_game_assets.py`, `npm test`, `npm run typecheck`, `npm run build`, and `npm run assets:extract`.

## Verified source facts

- `i.a(byte[], byte, byte)` begins scanning at byte 1 and skips each preceding record by the two-byte length prefix plus that record's declared length. It skips one byte inside the selected record, then decodes a token followed by packed codes, four shorts, three bytes, a short, and a count of three-byte records. JADX and `javap` agree on these offsets and operations.
- `/enm/data0`, `/enm/data1`, and `/enm/data2` each contain 43 indexed records (indices 0–42). The decoder writes one JSON file per source table and validates that each record ends exactly after its declared three-byte-record count.
- `ad` selects `/enm/data{m.g >= 2 ? 2 : m.g}` while loading map enemy definitions. `m.a()` sets the persisted mode byte `m.g` to 0 for a fresh start; the post-credits cycle path `m.c()` sets it to 1. The browser persists this byte, loads the matching extracted table, and starts mode 1 after the credits.
- In controlled REA browser scenario `ev_3cb271be87d2c6de909202b8240575c1d7bdee9df9db1581fdf50f3197439b5d`, a mode-1 save loaded through the title's Load Game route requested `/assets/generated/enemy-data/data1.json` with HTTP 200 and rendered map 0 after 8 seconds. The retained capture has no page exceptions or HTTP failures; its 3,000-event limit dropped 534 event records. This validates the saved-mode resource selection on browser resume, not mode-1 combat parity.
- In `ak`'s constructor, `f50a` is initialized from definition `f263a`; HP restoration also caps at `f263a`, establishing it as maximum HP. Enemy attack code reads `f264b`, subtracts `f265c` before applying the element matrix, and uses `f266d` in the hit/evasion chance. On death, `ak.l()` queues `f267e`, enemy ID and tile position only when `shapeCode != 2`. `ad` initializes its cadence field to 16; each map update decrements it, and a value below zero resets it to 16 while every queued delay loses 16. Respawn is therefore checked every 17 map updates and starts when the stored delay becomes negative. The source then looks up the enemy definition ID and tries randomized placement with inclusive offsets from -3 through 3, checking the map occupancy/collision grid. If placement fails, the queued delay resets to zero for another cadence attempt. Two-cell (`classCode == 2`) enemies at the right edge use the source special case at X−1. The converter preserves these fields as `classCode`, `shapeCode`, and `respawnDelay`.
- `t.a` contains this integer factor matrix, in tenths:

  ```text
  10 10 10 10
  10 10  6 13
  10 13 10  6
  10  6 13 10
  ```

- `ak.a(int, boolean, byte, boolean, byte, byte, an)` computes `max(0, power - enemyDefense)`, applies `value * t.a[playerElement][enemyElement] / 10` with Java integer truncation, then adds `value * k.b / 10` when its conditional flag is true. The ordinary `ak` path checks evasion with `roll[0,99] < min(50, enemyEvasion - (playerDexterity + player.o) - (k.e / 5) + 10)` before applying the hit. `au` overrides this path; its additional behavior and the conditional flag's purpose remain unresolved. `ak.a(int, byte)` uses the same element table for damage and enters the enemy death state at zero HP.
- In R10 the initial Ronin has `f59f=3` and `an.o=0`. The fresh-game type-0/id-0 ability is a `k`; its `d` parser sets inherited field `e` from an explicit zero argument. For enemy 24, the ordinary-path threshold therefore evaluates to 13, but no miss or RNG sequence was measured in R10.
- Raw game key `53` is statically routed by `ar` to `m.a(false)`, which queues the player's next action through `an.a(false)`. In controlled FreeJ2ME-Plus run R10, AWT Numpad5 (`101` → emulator internal `18` → raw `53`) was sent twice while the Ronin stood at tile `(9,30)` facing an adjacent map-27 Dust at `(10,30)`. Read-only snapshots tracked the live enemy-24 object from its original `(10,31)` placement: HP changed `43→32→21`, with its position unchanged during each action window. The R10 runtime observation confirms this input produces a repeatable hit in this starter encounter. Enemy table variant `data0`, record 24, has defense 5; the player snapshot's source attack-power field is 16, so the neutral-element formula predicts 11 damage, matching both observed reductions. This is one profile/target/action comparison, not a validation of all combat cases. See [R10 manifest](evidence/milestone-1.5/runtime-20261021/M15-SCN-0005-P1M-R10/manifest.json), [before](../../reference/screenshots/M15-SCN-0005-P1M-R10/before-action-east.png), [first hit](../../reference/screenshots/M15-SCN-0005-P1M-R10/after-raw53.png), and [repeat hit](../../reference/screenshots/M15-SCN-0005-P1M-R10/after-raw53-repeat.png).
- `ak.l()` walks the three-byte enemy records as cumulative thresholds and enqueues at most one death-time result. The decoder preserves these triples verbatim as `dropCandidates`; it does not assign meanings to the first two values.
- The remainder of `ak.l()` applies experience immediately: it computes `20 - (playerLevel - enemyRecord.f)`, caps that factor at 26, multiplies by `enemyRecord.f`, divides by two with Java integer truncation, then passes the result to `an.f()`. `an.f()` adds four times that amount to accumulated experience, consumes the current level threshold while enough remains, and invokes `an.r()` for each threshold. `an.n()` sets the threshold to `level³ - level² + 80×level`; `an.r()` increments level below 99, recalculates stats, awards three attribute points, and refills HP/SP. The source max-HP and max-SP formulas each grow by 12 per level while equipment bonuses stay fixed. The source also creates map drops for the selected table result, `enemyRecord.f * 3` currency, and a type-11 object; these are separate from the immediate experience award. FND-0010 maps the ground-item/pickup path and M32 verifies currency pickup in the browser.
- The converter now preserves the `.evt` enemy definition ID list and `(tileX, tileY, enemyId)` placements. 39 of the 72 event files contain placements. Map `m/6/00.evt` script 0 has the static command pair `[7,27,0]`, `[8,5,37]`, which requests map 27 at tile `(5,37)` under the verified opcode interpretation. Map 27 has 18 placements referencing enemy IDs 21 and 24. In emulator run R07, the sequence from the known outside spawn reached map 27 and the screen showed a nearby creature with the HUD label `Dust!` ([route screenshot](../../reference/screenshots/M15-SCN-0005-P1M-R07/map27-route-p7.png), [nearby screenshot](../../reference/screenshots/M15-SCN-0005-P1M-R07/map27-near-enemy.png)). This confirms the transfer route and visible enemy presentation only.

## Implementation and checks

- The converter emitted `enemy-data/data0.json`, `data1.json`, and `data2.json` under ignored local generated assets. Each contains 43 rows; the full asset manifest now reports 1,694 generated files.
- `web/src/world/combat.ts` parses the extracted enemy table, initializes independent HP per event placement, resolves a directly adjacent facing target, applies the ordinary `ak` evasion threshold, and updates HP through the confirmed defense/element path. The current `WorldScene` starter profile is the fresh-game Ronin against variant `data0`; raw Numpad5 and the touch Attack button use that resolver. At zero HP it records `death-pending`; after three source update returns, the fourth update hides the sprite and releases its occupancy. Eligible shapes then wait for the source respawn cadence, seek an available cell, return at max HP, and occupy their new footprint. M31/M32 award experience and create loot at the lethal-hit transition; the separate death animation remains unimplemented.
- Source `ak.a(int, byte)` queues `new av((byte)7, (short)4, (short)damage)` on a hit. `av.a(Graphics,int,int)` uses `q.a` for a four-paint damage number: its Y coordinate rises by four pixels per paint; the first two paints select the transparent `/img/etcui/007` font and the last two select `/img/etcui/005`. The latter uses seven-by-nine digit cells with six-pixel advance and centered alignment. `web/src/world/combat-feedback.ts` models four 71 ms gameplay paint intervals; `WorldScene` renders extracted 005 digit cells over the target for paints 2–3, then destroys them. This is source-derived animation timing and glyph data, not a pixel-verified port of source placement or the first two font calls.

## Limits and unresolved behavior

- R10 verifies two successful adjacent 11-HP hits against enemy 24 for the fresh-game Ronin profile. The web has per-placement HP and an ordinary-path evasion check, but M27–M30 use seeded save positions and do not compare combat or respawn RNG results to the J2ME runtime. M28 displays source-derived damage digits on a web hit, but popup placement, colors and timing have not been pixel-compared with J2ME. M30 restores enemy 24 at max HP after the source-derived delay, but the browser RNG is Phaser RNG and the position was not compared with the J2ME random stream. M29 implements the four-update delay before sprite removal and cell release. M30 implements the 17-update/16-unit timer cadence and checked random placement for a respawning enemy. M31 adds experience and level bookkeeping in the browser, but has not been compared with a source kill or level-up; separate enemy animation and ground drops remain unported. M37 later adds behavior 0/1 melee and the baseline Ronin incoming-damage path (see [FND-0015](FND-0015-enemy-melee-attacks.md)). Statuses, special enemy attacks/AI, skill selection, attack geometry outside the adjacent cases, RNG sequencing and behavior across other characters/gear/elements remain incomplete.
- AI, skill selection, status effects, random-number sequencing, attack geometry/timing, browser/source experience comparison, ground-drop/pickup rewards, and the meanings of the packed behavior codes and drop record values remain unresolved. The byte values above are traced for fresh start and post-credits cycle; other paths that may restore mode 2 or higher have not been observed.
- The exported label token and unclassified byte/bit fields retain source values; their player-facing meanings have not been established.
