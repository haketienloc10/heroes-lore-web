# FND-0040 — Map-82 source-created `bu` actor and removal callback

## Question

How does map 82 construct enemy 42, and what source event runs when it is defeated?

## Reference and method

- Reference JAR: `original/heroes-lore-v2.1.2.jar`, SHA-256 `7eb032297967f5d8382cc4f1ab5c3016459e01b235b42a3b88c6a8bfe46c5f61`.
- Read JADX output for `ad.java`, `bu.java`, `au.java`, `ak.java`, and `ag.java`; cross-checked the constructor, no-op AI override, removal callback, and death counter with `javap -classpath original/heroes-lore-v2.1.2.jar -c -p ad`, `bu`, and `au`.
- Inspected the extracted map-82 event operations and enemy record 42. The source actor uses local enemy animation slot 1, corresponding to extracted `/enm/spr/01`.

## Verified source facts

- The map-82 loader sets source data slot 1 to enemy ID 42, initializes four sprite states, then constructs `bu` at tile `(7,10)` with enemy ID 42 and slot 1. It sets source state 1 and facing 2.
- `bu.i()` is empty. Inherited `ak.n()` calls this method in the ordinary state-1 update, so `bu` does not acquire or pursue the player and has no subclass attack action.
- `bu` extends `au`. Its hit handler therefore follows the `au` response documented in M132 rather than the ordinary `ak` directional reaction.
- `bu.m()` sets the inherited death counter `q` to 16. `ak.n()` decrements positive `q` once per map update and invokes `l()` on the following update after the counter reaches zero.
- `bu.l()` first calls `au.l()` to remove the actor, then calls `ag.a((byte) 1)`. The `ag` dispatcher treats this as a direct type-0 marker; marker 1 addresses map 82's first trigger group.
- The indexed enemy record has source class width 1 and shape code 2, so the actor occupies one cell and does not enter the ordinary respawn queue after removal.
