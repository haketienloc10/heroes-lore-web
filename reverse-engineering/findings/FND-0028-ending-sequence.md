# FND-0028 — Source epilogue and credits sequence

## Question

What does event opcode 20 do at the end of the story, how are the character epilogue and shared credits paced, and how can the browser port hand the source event flow into that sequence?

## Source identity and tools

- JAR: `original/heroes-lore-v2.1.2.jar`, SHA-256 `7eb032297967f5d8382cc4f1ab5c3016459e01b235b42a3b88c6a8bfe46c5f61`.
- Examined JADX output `reverse-engineering/decompiled/sources/defpackage/ag.java`, `ar.java`, and `m.java`; inspected the hash-pinned generated map-08 event-operation and localized text-table assets.
- Relevant paths: `ag.m11a()` opcode dispatch, `ag` opcode-20 handler; `ar.g()` ending initialization; `ar.paint()` states 12/13; `ar.d(Graphics)` epilogue; `ar.e(Graphics)` credits; `ar.h()` shared credit/image loading; `m.a(int)` state transition handling.

## Evidence and conclusion

- `ag` labels opcode 20 `GAMEOVER`. Its handler stops the active event with `c()`, changes the cadence through `br.f158a.g()`, then requests screen state 12 with `m.a(12)`.
- Entering state 12 calls `ar.g()`: the game initializes `f82e` to `-16`, resets the epilogue cursor, and loads `/sgui/ed{heroClassId}`. In `ar.d(Graphics)`, 16 paints cover the screen from white toward black. The localized epilogue advances on key input; each `_N` record pauses the current page for that many frames, and a key can skip the remaining wait. At end of the character text it invokes `h()` and requests state 13.
- `ar.h()` loads shared strings from `/sgui/edsr` and selects `/img/end/{heroClassId-6}`. State 13 draws that image centered vertically, introduces ordinary credit lines every 5 game paints, scrolls each line upward 2 pixels per paint, and uses leading `-` / `=` records for 4 / 10 paint delays. A line is removed once its y position is below `-8`. After the final record and scrolling line disappear, the source queues game-start command 21 with mode 2. `m.e()` handles that command with `m.c()`, then returns to gameplay state 1 and reloads the world. `m.c()` sets `m.g` to 1, clears the quest/game bitfields and sets game flag 0, removes inventory item classes 18–21, restores current HP/SP to their calculated maxima, and returns the current hero to its class start tuple: class 6 `(map 0, tile 22,4)`, class 7 `(map 60, tile 5,36)`, class 8 `(map 77, tile 10,18)`. It also updates persisted byte `an.f55f`: `m.m106a()` returns zero when the current mode is 3 or greater; otherwise it counts quest flags `[2,5,8,...,59]` and game flags 100–105, multiplies by mode weight `[60,30,10]`, then integer-divides by class divisor 19 (class 6), 21 (class 7), or 16 (class 8). `m.c()` adds that award, narrows to a signed byte, then caps values above 100; the order means overflow can produce a negative result that is not capped. The byte is the first serialized player-data field. Pinned bytecode evidence is recorded in [the focused `javap` extract](evidence/milestone-1.5/javap-ending-clear-points.txt).
- The pinned generated `event-operations/6/08.json` map data has script 1 ending with `[30,17,0],[20,0,0]`: quest flag 17 is set before the ending opcode. The script is localized through the map-08 string-ID table. The browser dispatcher applies executed flag changes before transferring control to the ending scene.
- The extracted TDF ID lists are `text-tables/sgui/ed6.json`, `ed7.json`, `ed8.json`, and `edsr.json`. The generated locale currently contains the referenced English entries. The three extracted ending-art PNGs are each 1×1 pixels, matching the local extractor output; their visible source-runtime appearance is not established by this finding.

## Browser implementation

- `event-cutscene.ts` treats opcode 20 as a terminal `ending` status, after earlier commands and quest flags have run. `WorldScene` passes the modeled player state and hero class to the new `EndingScene`.
- `ending.ts` resolves the source string-ID tables, models the 20-frame-per-second fade, epilogue pause/confirmation blocks, and scrolling credit cadence. The source confirm key also starts the next cycle immediately during credits. When the roll completes or is confirmed, `EndingScene` prepares the source's next cycle, writes it to browser storage, and restarts `WorldScene` at the matching class start with mode 1. The modeled state carries forward, resets game/quest flags, restores HP/SP, removes inventory categories 18–21, and stores `m.g` so the world loads `data1`. Older saves default to mode 0.
- The browser now persists `completionPoints` alongside its modeled game state, defaulting it to zero for existing version-one saves. The ending handoff computes the award from the current mode and flags before resetting them, then applies Java signed-byte narrowing and the source's upper-only cap. The value is carried into the next cycle and subsequent saves.
