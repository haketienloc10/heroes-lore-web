# FND-0063 — Event dialogue controls and spacing

## Evidence

The checked-in source enables `ay.b` for the small event font; `ay.m33a()` suppresses `$`, `@` and `|` control characters during drawing and width calculation. Its `b.a(Vector, String, int)` wrapping keeps spaces inside lines and preserves a fitting short string as-is. This analysis reads checked-in source and generated class-6 event/language data; it does not inspect the original JAR or save files.

The active web formatter only removes `$` or `|` when immediately followed by a bracketed speaker, and its wrapping collapses whitespace. Eight event references on maps 34, 35 and 38 begin with `$` followed by seven spaces and a bracketed letter; the current web thus shows the control character and loses the indentation. The M815 opening-only substitution also incorrectly rewrites speaker names.

## Prepared change and limits

The [isolated patch](../../reference/screenshots/web-render/M819-dialogue-controls-and-spacing/prepared.patch) removes source control characters, keeps speaker labels, and uses source-shaped space-preserving word wrapping with a progress guard for an oversized glyph. It updates two existing speaker expectations; no repository tests were added or run. A read-only formatter observation shows all eight generated inscription strings retain their seven leading spaces after the control is removed ([observation](../../reference/screenshots/web-render/M819-dialogue-controls-and-spacing/inscription-observation.json)).

A static comparison of 729 generated dialogue/choice references at width 212 finds 34 whose wrapping changes; this includes repeated or trailing spaces and boundary cases ([scan](../../reference/screenshots/web-render/M819-dialogue-controls-and-spacing/wrapping-scan.json)). The scan describes impact, not source-runtime parity. In an isolated visible New Game, the first opening-dialogue frame remains RGB-identical to the R04 reference and the next state carries `[Ronin]` ([capture](../../reference/screenshots/web-render/M819-dialogue-controls-and-spacing/capture.json)). The eight inscriptions were not reached live, long-dialogue pagination has not been compared against J2ME, and this does not verify the full campaign. The patch supersedes M815 and was applied after M809 ended; it had been held while that page was active because Vite reloads on source edits. No in-game Save/Load, browser-storage inspection, gameplay-state seed, or original-JAR inspection was used.


## M823: Keep controls through wrapping and reveal

A further source review narrows M819's limits. For long strings, checked-in `b.a(...)` accumulates character widths before `ay` suppresses controls at drawing; stripping a marker before wrapping can therefore change a line break. A static model of that difference finds 47 generated class-6 event references whose line breaks can change, including opening string 1623 ([analysis](../../reference/screenshots/web-render/M819-dialogue-controls-and-spacing/control-width-analysis.json)). Source `bg.c()` also advances the next dialogue row by font height plus two pixels; the web used eight pixels.

The [M823 patch](../../reference/screenshots/web-render/M823-dialogue-source-wrapping/prepared.patch) was prepared against the now-applied M819/M818 worktree. It carries source control characters through event pagination and normal reveal, suppresses them while drawing, and uses the source row spacing. In a natural New Game on an isolated copy, the first fully revealed frame matched R04 at 0/76,800 differing RGB pixels. Two ordinary Enter advances reached the third dialogue, where the observed first row ends in `Is` and the second starts `it`; there is no source screenshot for that third line ([opening](../../reference/screenshots/web-render/M823-dialogue-source-wrapping/capture.json), [multiline](../../reference/screenshots/web-render/M823-dialogue-source-wrapping/multiline-capture.json)). TypeScript checking passed in the isolated copy. The patch was held during M821 to avoid reloading its active page, then applied after that run ended. M824 verifies the applied worktree below. No in-game Save/Load, browser-storage or local-save inspection, original-JAR inspection, or gameplay-state seed was used.

The refined prepared patch also returns no pages for empty text and drops the trailing empty row after a final newline, matching `b.a(...)`'s empty-string and vector behavior. A static scan finds 194 empty locale entries but none among the 715 generated opcode-1 references; these guards match the general helper behavior without affecting the scanned campaign dialogue.

## M825: Keep control widths on the short-text path

Review found that the paginator's short-text fast path measured text after `formatSourceDialogue` removed control markers. A short string could therefore skip a source wrap when the marker itself pushed the raw width over the line limit. The fast path now measures the raw input, consistent with wrapping longer source strings before drawing suppression. Two focused tests cover the width boundary and empty/trailing-newline behavior. `npm run test --workspace web -- tests/dialogue.test.ts` passes all 7 tests; root `npm run typecheck` and `git diff --check` also pass.

The M824 natural New Game capture was repeated after this correction. The first opening frame remains 0/76,800 changed RGB pixels against R04, the third dialogue still breaks after `Is`, and both browser windows record zero errors ([opening](../../reference/screenshots/web-render/M824-applied-dialogue-wrapping/capture.json), [third dialogue](../../reference/screenshots/web-render/M824-applied-dialogue-wrapping/multiline-capture.json)). This does not prove all dialogue wrapping or timing against the source runtime; the full repository suite, production build, and broader game parity remain open.

## M839: Match the source short-text width branch

Source `b.a(Vector, String, int)` uses inherited `ay.a(char[])` for its short-text optimization. With control suppression enabled on the event font, `$`, `@`, and `|` contribute no width on that branch, and a fitting string is retained unchanged. When wrapping is needed, the source loop instead adds raw `a(char)` widths before the renderer suppresses those controls. The prior M825 web fast path measured raw control widths in both cases, so a short control-rich string could wrap when the source keeps it on one line.

`paginateBitmapDialogue()` now measures the short fast path after control suppression when `sourceControls` is enabled, while leaving raw per-character widths in the wrapping loop. Regression tests cover both a fitting short string and the raw-width wrap boundary. The full suite passes at 59 files / 523 tests; typecheck, production build (1,281.40 kB main JS chunk, existing Vite >500 kB warning), and `git diff --check` pass. This is static-source-backed; the specific boundary case has not been captured in J2ME.
