# Ending clear-point bytecode from the pinned JAR

Source: `original/heroes-lore-v2.1.2.jar`
SHA-256: `7eb032297967f5d8382cc4f1ab5c3016459e01b235b42a3b88c6a8bfe46c5f61`
Command: `javap -classpath original/heroes-lore-v2.1.2.jar -c -p m an`

The serializer writes it as a byte and the restore path reads it as a signed byte:

`m.a(byte)` returns the clear-point award. It returns zero for modes 3 and above,
counts the 20 quest flags `2 + 3*i`, counts game flags 100 through 105, then
applies the mode weight and hero divisor. Integer division truncates toward zero:

The `m` static initializer sets `h` to `{60, 30, 10}`. The post-credits `m.c()`
adds the award to the persisted byte, narrows with `i2b`, then applies only an
upper cap of 100. The order matters because signed-byte overflow can make the
stored value negative before the cap check:
