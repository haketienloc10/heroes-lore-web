# FND-0042 — Weapon procs, enemy statuses, and active-skill elements

## Question

How do the source weapon subtype values affect a player hit, which enemy status effects do they apply, and which element is used for ordinary player attacks?

## Reference and method

- Reference JAR: `original/heroes-lore-v2.1.2.jar`, SHA-256 `7eb032297967f5d8382cc4f1ab5c3016459e01b235b42a3b88c6a8bfe46c5f61`.
- Static inspection used the repository's decompiled `an.java`, `s.java`, `k.java`, `ak.java`, `n.java`, `ce.java`, `o.java`, `av.java`, `cd.java`, and `q.java`.
- No J2ME runtime comparison was performed.

## Source evidence

- `s.i` gives weapon-proc chance percentages `[20,16,6,13,13,10,10,10,10]` for codes 0–8. `s.h` maps codes 0, 1, 5, 6, and 7 to enemy status IDs 0, 1, 4, 3, and 2; codes 2, 3, 4, and 8 do not apply an enemy status.
- The weapon subclass `k` stores subtype bytes `a`, `b`, and `c`; `c` is the proc code. Category-3 subclass `s` stores its proc code in byte `c`. `an.m16a()` checks the weapon first and checks category 3 only if the weapon has no proc or its roll fails.
- Each attack event in `an.p()` calculates attack power, selects a proc, then rolls critical. For code 8, when `m108a()` finds an enemy in the cell directly ahead, the player loses `maxHP / 25` once before the attack resolver runs. At a successful hit, `ak.a(...)` replaces the calculated damage with the target's attack for code 2, drains SP by 80% of calculated damage for code 3, drains HP by half of calculated damage for code 4, and doubles calculated damage for code 8.
- `ak.a(...)` applies mapped statuses only after its evasion roll succeeds. `n.m110a()` refreshes an existing status timer instead of adding a duplicate. `ce` durations for enemy status IDs 0–4 are 40 updates. Status 3 deals a random 15–25 damage every eighth update, including update 40 before expiry.
- The ordinary `ak.d()` update calls its private `ak.s()` before `ak.n()`. `ak.s()` advances attached `ce` timers, applies poison, then removes expired effects and clears their flags. `au.d()` does not call `ak.s()`; map-specific subclasses that override `d()` and call `ak.n()`/`ak.o()` also bypass it.
- `ak.n()` resets to its idle action while status 0 or 2 is active. `ak.a(boolean)` doubles the cooldown interval while status 1 is active. Status 4 subtracts half the enemy's defense instead of its full defense during ordinary incoming damage calculation. Ordinary `ak` incoming-hit paths call `ak.t()` first: the ordinary attack clears status 0 before evasion, while direct `ak.a(int, byte)` skill damage clears it before applying elemental damage. The `au` overrides do not call `ak.t()`.
- `au.a(int, byte)` applies the elemental multiplier and damage directly without waking status 0. Its multi-argument hit override uses the full enemy defense, compares the random roll with twice the ordinary evasion expression without the ordinary 50-point cap, and handles only proc codes 3, 4, and 8. Code 3 drains 30% of calculated damage here, compared with 80% in `ak.a(...)`; code 4 still drains half of calculated damage and code 8 doubles it. The `au` override does not replace code-2 damage with enemy attack or apply the `s.h` mapped statuses. These overrides are inherited by the special `au` subclasses used by the map-11/13/15/82 encounters.
- Ordinary player hits use the active skill's element from `o.m112a()`: skill IDs 0/3 map to element 1, 1/4 to element 2, 2/5 to element 3; other IDs return neutral element 0. The class-8 `h` projectile retains the player actor reference, so its hit callback reads the active skill element when the projectile reaches an enemy.
- When `an.p()` selects proc 2, 3, 4, or 8 and `m108a()` finds an enemy directly ahead, it adds `av(10, 8, imageIndex)` with image indices 8, 10, 11, or 0. `cd` loads these images from `/img/emoti`; `av.a(Graphics, x, y)` paints at the actor origin and 39 pixels above it, alternating the vertical offset by `frame % 2`, and expires after eight paints. Proc 8 also adds a negative `av(7)` HP-cost number; `q.a()` selects styles 4 then 2 for negative values.
- The pinned `/img/etcui` atlas confirms the signed styles' appearance. Styles 3/1 use images 007/005, and styles 4/2 use images 008/006. Extracted images 006, 007, and 008 are each 1×1 with palette index 0 transparent; negative values therefore have no visible number frame in this JAR, while the positive style 1 uses the 70×9 digit strip in image 005.

- Class-8 heavy projectiles carry the selected proc code through each segment. Their attack power and critical result remain captured at launch; the active-skill element is read again at impact.
- Basic player hits now use the active skill's source element mapping. Focused Vitest coverage checks proc draw ordering, damage/resource/status effects, wake-on-miss, status defense, poison duration/pulses, status refresh, blocked AI, cooldown slowdown, projectile proc retention, and the six-element mapping.
- M143 extends status interruption to the custom map-13 AF/BC/CC state model. The pinned `bc.d()` bytecode increments the inherited frame, calls `ak.n()`, then `ak.o()`; the blocked branch in `ak.n()` calls `ak.a(false)`, while `ak.o()` then consumes one cooldown update. The web returns the custom state to idle on status 0/2, preserves subclass fields, and uses twice the base cooldown while status 1 overlaps an interruption or attack completion. ## Limits

- These are static-source-backed implementation facts, not J2ME runtime parity evidence. There is no controlled browser combat replay or J2ME comparison for proc frequency, damage, resource costs, status timing, status icons, or elemental damage.
- The current Java-compatible range and raw entity streams remain separate web streams; exact full-game RNG draw parity for weapon procs and multi-target attacks is unverified. Negative `av(7)` values use transparent source images and therefore remain visually blank in the browser; proc visual timing has no browser or J2ME comparison.
- The bytecode establishes ordinary `ak` status-timer ordering, but no controlled J2ME runtime comparison verifies status timing, icons, or combat. Exact weapon-proc RNG parity remains open.
- The broader game remains in progress; this finding does not complete combat or the campaign.
