# FND-0061 — Alternate Map42 checkpoint profile and equipment access

## Question

What equipment, wallet, attributes, and skills are present in the visible Map42 checkpoint used by the M717 browser profile, and can its wallet buy a class-6 weapon upgrade?

## Method and observations

- M747 restores the checkpoint through the ordinary title Load Game UI in the disposable M717 browser profile, then reads the active `WorldScene` state and captures the screen. No Save Game action, browser-storage access, gameplay-state mutation, or original JAR access was used.
- The checkpoint loads at Map42 `(8,2)`, level 6, 312/312 HP, and 462 G. Its attributes are Power 8, HP 20, Agility 3, and Will 4. Fireball is rank 5 and active; Heal is rank 3. The bag contains two category-11/item-0 Mithril and one category-2/item-0 item; the equipped weapon is category 0/item 0, with category 5/item 0, category 6/item 0, and category 4/item 0 in the other occupied equipment slots.
- The saved profile is distinct from the level-8, 300-G checkpoint used for M693–M705. Those observations must not be combined into a single character build.
- The generated class-6 Map42 event data has no NPC placements or shop/service opcode. The app-loaded commerce catalog lists class-6 category-0/item-1 at 400 G, so this checkpoint has enough currency for that item if the player reaches a shop. Existing service handoffs are in maps 79–81; M747 does not prove a route from this checkpoint to a service or record a purchase. The catalog/formula audit in [FND-0060](FND-0060-map42-fireball-exchange.md) shows that this first weapon tier is still below the power projected to damage Map42 type-2 enemies and Map15 boss 39.
- The live state snapshot contains nine Map42 enemies. It is a loaded checkpoint audit, not evidence of how this wallet, equipment, or skill progression was earned naturally.
- M748 tests the return from this upper checkpoint by holding Right toward the Map41 marker. The player reaches only `(10,2)`, where the loaded collision row blocks x=11–36; the input never transfers to Map41. HP remains 312 through 269 ms, then later samples fall to 161, 12, and 0 over 8.8 seconds. A post-game-over read shows enemy order 1 at `(9,3)`, but the fatal damage source is not isolated. The browser records zero exceptions, console errors, failed requests, and bad responses. This rules out a straight eastward path along row 2; it does not establish that no alternate route exists ([M748 capture](../../reference/screenshots/web-render/M748-map42-to-map41-exit/capture.json), [route trace](../../reference/screenshots/web-render/M748-map42-to-map41-exit/route-trace.json), [dynamic path observation](../../reference/screenshots/web-render/M748-map42-to-map41-exit/post-failure-path-observation.json)).
- M749 retries the Map42 upper return with a risk-weighted route planner. The runner reaches `(31,8)`, then its own path search stops when all next cells are blocked by the live collision/occupied-cell model; a later read finds 0 HP at the same tile and the title menu active. This is a partial harness observation: movement samples and browser error counters were not serialized, so it does not prove that the game world has no route or identify the fatal attacker ([partial capture](../../reference/screenshots/web-render/M749-map42-upper-risk-route/capture.json), [partial trace](../../reference/screenshots/web-render/M749-map42-upper-risk-route/partial-route-trace.json)).

Evidence: [M747 capture manifest](../../reference/screenshots/web-render/M747-map42-checkpoint-profile/capture.json), [Map42 screenshot](../../reference/screenshots/web-render/M747-map42-checkpoint-profile/01-map42-visible-load.png), and [generated Map42 event data](../../web/public/assets/generated/event-operations/6/42.json).
