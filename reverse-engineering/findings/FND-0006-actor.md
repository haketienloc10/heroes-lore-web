## Source facts

1. `m.a(boolean, byte, boolean[])` creates `an(0, 0, 8, 8, characterId)`. `cj` stores world pixel coordinates, derives grid coordinates with `>> 4`, and tracks whether either coordinate is between 16-pixel cell boundaries. The player inherits a one-cell occupancy footprint.
2. `n.a()` starts in entity state `1` and direction `2`. Direction vectors in `t` map `1=up`, `2=down`, `3=left`, `4=right`. `m.b(direction)` starts movement state `2` from idle or queues a direction while already moving; `m.h()` queues a stop.
3. `an.d()` advances a state-2/state-4 actor with `super.a(8)`, which changes one world coordinate by 8 pixels in the active direction. `ad.a(int,int)` admits a cell only when it is in bounds, the signed runtime collision value is nonnegative, and the occupancy grid is empty. `ad.a(n,direction)` checks the actor's next occupied cell.
4. `an.a(Graphics,...)` draws a shadow, then iterates render layers 0–8 in order. Layer 7 uses the nested-frame renderer `ar.b`; other layers use `ar.a`. Layers 6 and 7 are skipped when `ad.f7c` is false. `bt.j()` and `bt.k()` load the body (`b`), armor (`aN`), head (`hA`/`hB` plus `hN` images), weapon (`wN`) and effect (`e`) data; source lookup tables map equipped item IDs to the atlas groups. `bt.f169a` and `bt.b` select `/c1`, `/c2`, or `/c3` sprite resources for hero IDs 6–8. `bt.j()` also loads a shield for class 8 using `f173b` and `/c3/i/sN`. The map's first header byte is its tileset ID, and `ad` sets `f7c` unless that byte is 1, 5, 9 or 15. The converter preserves the `.s` layouts as JSON, including signed offsets, frame lists and mirrored-frame flags.
5. SCN-0004 measured a 71 ms gameplay pacing period on a separate runtime route/profile. That period is evidence for the browser update step, not a dedicated measurement of actor travel speed in HOUSE-EXIT-001.
6. `an.a(Graphics,...)` renders actor states 1 and 4 with animation slot 0, state 2 with slot 1, and state 6 with slot 2. State 3 uses the action-state renderer in `an.e(Graphics,...)`, which selects the attack slots. The per-layer frame index is `36 * animationSlot + 9 * (direction - 1)`; layers 6 and 7 remain tileset-gated.
7. In the state-6 render branch, `an.a(Graphics,...)` calls the layered renderer with animation slot 2 and direction 1 regardless of the actor's previous facing. `an.d()` resets the actor frame cursor to 0 on each death update, so the displayed death pose uses direction slot 0 and frame 0.

## Implemented model

- The Phaser scene loads map 64, the region-6 base collision grid, its static decorations, and the selected character-sheet body, armor, both head layouts, weapon, effect layout and atlas PNGs. M88 composes the class-6 starter body/head/weapon frames and optional armor/effect parts in the source layer order, applies the source equipment-ID-to-atlas lookups, and gates layers 6/7 from the map tileset ID. M304 selects `/c1`–`/c3` layout/atlas directories from the saved hero class when their source layouts are present, extends palette extraction to those class directories, and renders the class-8 shield via `f173b` when its `/c3` layout and shield atlases exist. It also hides the opening script's screen-clear overlay after a successful map transfer; otherwise the BED destination stayed black after W/Skip. M89 selects source animation slot 0 while idle and slot 1 while moving, retaining the source combo slots for active attacks. In `an.a(Graphics,...)`, states 1 and 4 share slot 0, state 2 uses slot 1, state 3 uses the combo renderer, state 6 uses death slot 2, and state 5 draws no player body. The checked-in player update paths enter states 1/2/3/6, so there is no distinct missing state-4 animation.
- The initial world coordinate `(144,128)` / cell `(9,8)` is inferred by aligning the reconstructed sprite to the BED screenshot and the 16-pixel map grid. The pinned game bytecode constructs the actor at `(0,0)`; a later map-entry event assigns the actual location, and that operation has not yet been traced.
- The engine-independent actor model advances in 8-pixel half-tile steps at a 71 ms update period. It checks event-selected map collision and visible static NPC/enemy occupancy at aligned cell boundaries, maintains facing direction, queues turns to a boundary and finishes the current tile on release. Occupancy changes during gameplay and dynamic entity footprints are not yet integrated.
- Ordered cutscene waits now advance on actor update boundaries, after the actor receives that update. This keeps scripted direction/wait/stop sequences from losing an actor step when a wait expires during a rendered frame. M192 demonstrates the map-64 recovery route in Chromium; source runtime timing has not been compared.
- M149 selects the extracted state-6 player pose when HP reaches zero: animation slot 2, source direction slot 0, frame 0. The same pose remains on screen through the existing 24-update death delay and game-over reveal.
- Arrow keys and WASD drive the actor. The scene camera tracks and clamps to the map bounds; its complete original camera modes are not modeled.

## Comparison and limits

The 240×320 Playwright capture has its static room aligned to the BED fixture with zero translation. A custom nearest-pixel RGB comparison returned average per-channel absolute difference `1` over the capture with the starter-avatar rectangle excluded for the BED comparison. In the first-Down checkpoint, the detected cyan head spans rows 203–213 in the reference and 205–215 in the browser; movement lands in the same lower room region, with a 2-pixel sprite offset. This is a narrow comparison, not a full pixel diff: HUD, animation timing, NPCs, events and physical-device rendering are not covered.

M490 rechecked that first-Down estimate against the newer M461 screenshot using exact decoded pixel comparison. The 2-pixel head displacement is not present in that capture: all pixels at rows 203–218 match. Its 47 non-HUD differences are within the avatar rectangle at x=112–127, y=219–229; 714 other differences are in the HUD band at y=295–319. The BED and outside pairs also have 714 HUD differences each, while their non-HUD counts are 47 and 247. This does not identify the remaining HUD or avatar differences, establish animation timing, or prove broader J2ME parity. Inputs, hashes and counts are recorded in the [M490 comparison report](../../reference/screenshots/web-render/M490-house-visual-diff/analysis.json). M493 attributes and reduces most of the BED HUD mismatch: checked-in `ar.java` sets the HP/SP width to `q.g - 67` (173 at 240 px), while the web HUD had used 95 px; its zero-EXP `drawLine(3,y,2,y)` also paints both endpoints. The updated browser frame has 278 HUD differences and the same 47 player-image differences (325 total versus 761/714/47 before); hashes and regional metrics are in the [M493 report](../../reference/screenshots/web-render/M493-hud-resource-bars/analysis.json).

The reference and browser each move 91 screen pixels in the detected head rows across the one-second Down action; the browser uses the model period above. This does not establish exact callback-to-movement cadence: the original session was a single input run and the browser uses a separate scheduler. M89 replaces the old visual-only default slot with the bytecode-mapped idle and walking slots. Player animation timing and J2ME pixel parity remain open; the M88 capture predates this slot correction and remains evidence for layer composition and the screen-transfer fix only. M88's controlled New Game → W/Skip replay captures map 64 with the Ronin and starter weapon visible and no page errors or failed requests; see [capture manifest](../../reference/screenshots/web-render/M88-player-equipment-render/capture.json). It does not establish J2ME pixel parity.

The current generated asset manifest contains only the `c1` layouts/atlases, so class-7/8 saves still use the `c1` fallback and have no runtime appearance evidence. Class-8 shield rendering is implemented for a complete `c3` shield bundle, which is absent locally. Non-default gear appearances and J2ME sprite comparison remain open.

M311 adds `tools/audit_hero_render_coverage.mjs`, which validates the current class-6 body, armor, helmet, weapon and skill-element layout selections against generated atlas images. It checks all 15 category-3 armor items, 16 category-6 helmet items, 110 weapon catalog entries and four skill elements across 55 layout/folder combinations. All 256 unique referenced class-6 atlas images exist. The New Game script skip now transitions to map 64/cell `(9,8)`, and the house-exit event transitions to map 0/cell `(26,24)`. M20 replays both transitions from the browser menu. The map-64 source entry position is established by script 9; its actor pixel alignment is still inferred from screenshots. The HUD now redraws the modeled HP/SP/EXP values, selected quick-item count, and active skill icon as those states change (see [FND-0009](FND-0009-combat-data.md), [FND-0011](FND-0011-quick-items.md), [FND-0015](FND-0015-enemy-melee-attacks.md), and [FND-0038](FND-0038-player-skill-actions.md)). The initial HUD has a narrow J2ME image comparison; dynamic HUD changes have browser evidence but no J2ME comparison. Runtime collision/occupancy changes, broader NPC behavior, campaign state, full save/load and most of the game remain incomplete.
